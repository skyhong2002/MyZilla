# 個人內容洞察

`/dashboard.html` 的總覽先呈現持續關注、兩期變化與長期回訪三張卡；洞察頁整合五個面向。網站排行與既有歷史保留，無前景時間時顯示「尚未記錄」。分析只在自己的伺服器執行，不呼叫外部 AI 或抓取文章全文（總覽上方的 [AI 週回顧](ai-digest.md) 另行由排程產生），也不對朋友或公開分享開放這些新資料。

## 五個面向

- **興趣地圖**：主題規則比對標題與 URL path；另以 Intl.Segmenter 擷取標題關鍵詞，排除常見介面字詞、數字代碼、網站名稱及部分站名尾綴。自動關鍵詞須至少出現於三個不同頁面、兩個主機；呈現的主題須至少跨兩天、兩頁。主題以活躍日數 + 2 × log2(頁面數 + 1) + 3 × 月份數排序，不用 raw visit 數推定興趣強度。可改名、標成工作需要、排除或恢復；工作標記不會刪除主題，但不作總覽首張推薦。
- **探索路徑**：依裝置 ID、瀏覽器、profile 分組，同組相鄰內容造訪間隔不超過 30 分鐘為一段；至少三個不同頁面，其中至少兩頁屬同一個已呈現的主題。重訪同一頁只保留該段第一次的時間；不跨來源拼接。這是時間關聯，並無 tab/referrer 證據，不能聲稱確定閱讀順序或因果。卡片先顯示五步，展開依據分頁可讀全部步驟。
- **近期變化**：本期與前一期比較不同 canonical URL × 當地日期的數量與占比，分母為各期全部合格內容頁面日；不同主題可重疊，不加總為 100%。每個主題兩期合計至少三個頁面日，占比變動至少一個百分點（或其中一期為零）。兩期任一期完全無合格內容時不給變化結論。「全部」以最後一筆資料時間為基準，比較最近 30 × 24 小時與前 30 × 24 小時；指定期間則比較同長度前一期，畫面列出日期。「本期出現」不等於一生首次興趣。
- **興趣交集**：兩個主題在同一 canonical URL 的內容線索中共現，至少兩頁且跨兩天，按共同活躍日與頁數排序；展開直接查看共同頁面。沒有他人樣本，不能作人口稀有度或人格判斷。
- **長期線索**：在所選期間同一頁面至少跨兩個月份、三個不同日期回訪，按月份與活躍日排序。距最後一筆資料至少 30 天沒有回訪時，提示「值得找回」。這一版以頁面為單位，未作作者實體辨識。

## 分析邊界

讀取帳號全部 visit rows，不截斷來源匯入。非 HTTP(S)、帶使用者密碼的 URL、登入／OAuth 回呼、IP／localhost 工具頁、已知平台首頁／郵件收件匣、空白標題等不參與內容分析，各項排除數量在「分析依據與範圍」可見。原始事件不變動。URL 僅移除已知追蹤參數（utm_*、fbclid、gclid、msclkid），保留其他參數和 fragment；同 URL 同一天跨 profiles 重複不增加主題或變化權重。

資料沒有完整正文。標題關鍵詞可能含糊或破碎、規則可能分類不準、僅在一個網站出現的陌生主題可能漏判；使用者修正比推測更優先。同一 URL 的標題可能隨時間變更，目前聚合曾出現的標題線索，顯示最新標題；不能把結果當作已驗證的閱讀內容或喜好。持續使用的功能頁即使未命中工具排除規則，也可能成為長期線索。

各面向支援全文字串搜尋、每批 12 項的前後分頁；API limit 上限 100 只限制單次顯示量，沒有總結果上限。證據每頁 20 項，沒有總頁數截斷。初次計算正式 100,665 筆資料約 2–3 秒；程序內快取最多兩個帳號、120 秒，帳號、期間、時區、資料筆數／最新時間與修正值均納入快取判斷。

## 資料與 API

- `GET /api/insights?from=0&to=<毫秒>&zone=Asia/Taipei&q=&offset=0&limit=12`
- `GET /api/insights/evidence` 使用同一期間／時區，另帶 `topic`、`offset`。
- `PUT /api/insights/feedback`：`{topic,label,mode}`，mode 是 interest/work/exclude。
- `DELETE /api/insights/feedback/:topic` 恢復自動判斷。

所有端點要求既有 Bearer 身分，資料依帳號 Repository 取得。同步金鑰可讀自己的分析（其原本已有歷史讀取權），不能修改回饋。`insight_feedback` 僅存帳號、主題 ID、名稱與選擇；SQLite 一致性備份涵蓋此表，原始 `events` 不修改。

`src/insights/analyze.ts` 為純分析，`routes.ts` 處理帳號範圍、快取、查詢與回饋；`src/ui/personal-insights.ts` 呈現五面向與證據操作。`npm run test:insights` 以暫存資料庫驗證瀏覽器流程；正式資料僅供唯讀驗證與對帳，不寫入測試回饋。


## 歷史停留推估

回顧頁的「03 / 留下的時間」及總覽新增歷史推估，以同一裝置 ID／瀏覽器／profile 的相鄰 visit 計算：0 < 下一筆時間 − 本筆時間 < 60 或 180 秒，將時間差歸給本筆 URL。相同安全網址的有效區間加總，提供標題／URL 搜尋及每頁 50 筆的完整分頁。預設 180 秒，門檻存於目前分頁的 sessionStorage。

剛好等於門檻、超過門檻或最後一筆沒有後續者不補值、不封頂；同 URL 同時間去重，同時間多個不同 URL 不分配其後區間。下一筆即使是內部頁面仍作為前一頁的結束界線，但內部／非安全 HTTP(S) 頁面不產生推估時長。不跨 profiles 或裝置拼接，不要求前後頁相同網站。查詢先保留期間外的前後鄰居，再將合格區間裁切至查詢期間，避免邊界遺失或超算。

`GET /api/dwell?from=<ms>&to=<ms>&threshold=180&offset=0&q=` 使用既有帳號 Bearer 認證；limit 固定 50，totalMilliseconds／totalPages 為目前期間完整估算，matchedPages 是搜尋後頁數。每個頁面回傳 milliseconds、intervals；無法估算的頁面不冒充零停留。此 API 唯讀計算，不建立 attention 事件，也不改寫原始歷史。

多分頁、背景開頁、重新整理、閒置及跨 profiles 重疊都可能影響結果，因此 UI 明示「歷史推估」，與實際捕捉的前景時間分開、不加總。這也不是重建 tab/referrer 導覽圖的證據。
